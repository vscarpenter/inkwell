# Inkwell 3.5.0 — Adoption Release — Design

Date: 2026-08-27
Status: approved (maintainer approved the complete design-system review)
Source: repository-wide review of the public CSS API, reference pages, consumer and agent instructions, release drift, accessibility, responsive behavior, metadata, and CI coverage.

## Outcome

Inkwell 3.5.0 makes the current design system trustworthy to adopt. The release aligns the versioned install path with the documented API, turns the example gallery into a reference implementation, supplies reusable interaction recipes for the few components that require JavaScript, and converts documentation expectations into executable checks.

The release remains framework-free and build-free for consumers. Its Node scripts and browser tests are maintainer-only verification tools.

## Compatibility contract

- The canonical pure-CSS install remains `inkwell.css` + its two sibling imports.
- `tokens.css` remains a deprecated compatibility alias until 4.0.
- Existing component selectors remain supported.
- Tailwind's legacy `border-hair` utility remains supported until 4.0, but `border-inkwell` becomes the preferred, unambiguous name for the 1.5px signature border.
- Interaction JavaScript is optional. Static CSS components remain useful without it.
- Browser support remains Chrome/Edge 123, Firefox 120, and Safari 17.5 or newer.

## Release scope

### One public version

All canonical CSS headers, generated metadata, footer stamps, consumer examples, agent instructions, component metadata, and raw GitHub URLs identify 3.5.0. The release notes include everything accumulated since 3.0.1, including Azure, deployment metadata, callouts, findings, carousel, app shell, and this adoption work.

### A generated component reference

`component-manifest.json` is the machine-readable catalog for public component families. It records selectors, version introduced, anatomy, modifiers, states, accessibility requirements, JavaScript requirements, and copyable markup.

`scripts/build-components-reference.mjs` generates the catalog body in `examples/components.html` and supports `--check`. The page is a practical adoption surface, not a visual inventory: each entry tells consumers what to copy and what responsibilities stay with their markup or JavaScript.

### Portable interaction recipes

`inkwell-interactions.js` provides dependency-free tabs, carousel, and declarative dialog behavior. It initializes idempotently, exposes `window.InkwellInteractions.init(root)`, and auto-initializes the document. The examples consume this file instead of carrying separate implementations.

The interaction module owns behavior and ARIA state updates; the HTML owns useful labels, relationships, and initial state. Native `<details>` disclosures need no JavaScript.

### Reference-quality examples

Every published HTML page has:

- one visible `h1` and one `main` landmark;
- a working skip link;
- a canonical URL and theme color metadata;
- valid deployment/version footer markers;
- named controls and complete error relationships;
- no page-level horizontal overflow at 375 CSS pixels.

Dense tables may scroll inside `.tbl-scroll`. App-shell grids allow their children to shrink. Coarse-pointer devices receive at least 44 by 44 CSS pixel interactive targets without making desktop layouts artificially loose.

### Disclosure promotion

The native `<details>` pattern becomes `.disclosure`, with `<summary>` as its trigger. The landing FAQ and component reference use the shared primitive. Menu, progress, and meter components stay in the backlog until a concrete product need defines their API.

### Enforceable repository contract

`scripts/check-system-contract.mjs` verifies release alignment, source/example mirror parity, manifest/CSS parity, reference-page semantics, form error relationships, local links, Tailwind aliases, and stale documentation claims.

CI runs all zero-dependency generators and checks for every repository change. A Playwright smoke suite verifies reference interactions, themes, palettes, landmarks, and mobile overflow in Chromium. Pages deployment runs the same static gates before assembling its artifact.

## Information architecture

The gallery has three showcase surfaces:

- `preview.html`: visual inventory and maintainer review surface;
- `examples/components.html`: adoption reference with API contracts and copyable markup;
- `examples/tailwind.html`: Tailwind v4 integration proof.

The remaining pages demonstrate complete product and content patterns. `examples/docs.html` describes the current system and routes readers to the component reference instead of duplicating or inventing API facts.

## Non-goals

- No package manager, bundler, framework wrapper, CDN dependency, webfont, icon package, or generated image is added.
- No breaking selector removals land in 3.5.0.
- The release does not invent menu, progress, meter, toast, or dropdown APIs without consumer evidence.
- The design language is refined only where adoption, accessibility, or responsive correctness requires it.

## Acceptance criteria

1. All generated-file, contract, contrast, and deployment-marker checks pass from a clean worktree.
2. The Playwright suite passes at desktop and mobile sizes with no console errors or page-level horizontal overflow.
3. Every public interaction works by keyboard and maintains the documented ARIA relationships.
4. The examples mirror the canonical distributable files byte-for-byte.
5. `git diff --check` passes and the final commit is tagged locally as `v3.5.0`.
